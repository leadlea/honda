# 要件定義書

## はじめに

本MVPは、双日テックイノベーション株式会社におけるAI内製化支援の一環として、
社内にいるAI人材候補（社員）を発掘し、本人の自薦応募を起点に、複数のAIポジション（AI CoE／各部門AI担当／AIプロジェクト）へ適材配置するための
「AI人材発掘・配置マッチングMVP（AI CoE支援）」です。

既存のMVP機能（AIスキル棚卸し、AIスキルポートフォリオ、AIポジション推薦、自薦応募、検索・閲覧、通知）を前提に、
画面・文書・メッセージ上の日本語表現を本目的に沿って統一します。

※重要：コード、プログラム、ロジック、API構造、データベーススキーマは一切変更しません。
本書は「日本語文言・用語・メッセージトーン」の更新のみを対象とします。

## 用語集

- **System**: 双日テックイノベーション：AI人材発掘・配置マッチングMVP（AI CoE支援）
- **Frontend**: React TypeScriptで構築されたユーザーインターフェース
- **Backend**: AWS Lambda上のPython APIサービス
- **User**: 社内AI人材候補（社員）およびAIポジションオーナー（各部門／AI CoE）
- **Branding_Element**: 文言、メッセージトーンなどのブランド構成要素
- **Legacy_Term**: 旧MVP時代の用語（旧称・旧ラベル）
- **New_Term**: 新「AI人材発掘・配置マッチングMVP（AI CoE支援）」の用語

## 要件

### 要件 1: フロントエンド文言更新

**ユーザーストーリー:** 社内AI人材候補（社員）として、自分のスキルを整理し、自薦応募できるように、すべての画面で新しい用語を見たい。

#### 受入基準

1. WHEN ユーザーがアプリケーションにアクセスする THEN System SHALL 「AI人材発掘・配置マッチングMVP（AI CoE支援）」をアプリケーションタイトルとして表示する
2. WHEN ユーザーがナビゲーションを見る THEN System SHALL 「登録人材」を「社内AI人材候補」に、「問診」を「AIスキル棚卸し（セルフ診断）」に表示する
3. WHEN ユーザーがダッシュボードを見る THEN System SHALL すべての統計表示とメッセージで新しい用語を使用する
4. WHEN ユーザーがプロフィール管理画面を見る THEN System SHALL 「スキルポートフォリオ」を「AIスキルポートフォリオ」として表示する
5. WHEN ユーザーが推薦システムを見る THEN System SHALL 「参画機会レコメンド」を「AIポジション／プロジェクト レコメンド」として表示する

### 要件 2: 応募システム用語更新（自薦応募）

**ユーザーストーリー:** 社内AI人材候補（社員）として、自薦応募のプロセスを理解するために、明確で統一された用語を見たい。

#### 受入基準

1. WHEN ユーザーが応募機能を使用する THEN System SHALL 「応募」を「自薦応募」として表示する
2. WHEN ユーザーが興味表明機能を使用する THEN System SHALL 「興味表明」を「応募意向」として表示する
3. WHEN ユーザーが応募状況を確認する THEN System SHALL すべてのステータス表示で新しい用語を使用する

### 要件 3: 社内ポジション公開・検索 用語更新（部門横断）

**ユーザーストーリー:** AIポジションオーナー（各部門／AI CoE）として、社内から適任者を見つけるために、統一された用語で検索・閲覧したい。

#### 受入基準

1. WHEN AIポジションオーナーがポジション公開・検索画面にアクセスする THEN System SHALL 「登録人材検索」を「社内AI人材候補検索」として表示する
2. WHEN AIポジションオーナーが検索結果を見る THEN System SHALL すべての人材関連用語で新しい用語を使用する

### 要件 4: バックエンドメッセージ更新

**ユーザーストーリー:** AI CoE運営／管理者として、ログとAPIレスポンスで統一された用語を見たい。

#### 受入基準

1. WHEN APIがエラーレスポンスを返す THEN System SHALL 新しい用語を使用したエラーメッセージを返す
2. WHEN APIが成功レスポンスを返す THEN System SHALL 新しい用語を使用した成功メッセージを返す
3. WHEN システムがログを出力する THEN System SHALL すべてのログメッセージで新しい用語を使用する

### 要件 5: AI生成コンテンツ更新

**ユーザーストーリー:** 社内AI人材候補（社員）として、AI生成コンテンツでも一貫したメッセージトーンで支援を受けたい。

#### 受入基準

1. WHEN AIがスキル棚卸しコンテンツを生成する THEN System SHALL 新しい用語とメッセージトーンを使用する
2. WHEN AIがレコメンド理由を生成する THEN System SHALL 「内製化を前進させるための適材配置」という文脈を反映する
3. WHEN AIが（見出し／肩書き等の）表現を生成する THEN System SHALL 「AIスキルポートフォリオ」の文脈で適切な用語を使用する

### 要件 6: メッセージトーン統一（双日TI向け）

**ユーザーストーリー:** すべてのユーザーとして、信頼感があり、社内利用に適した一貫したトーンで利用したい。

#### 受入基準

1. WHEN ユーザーがアプリケーションを使用する THEN System SHALL 社内向けの信頼感あるトーン（過度に煽らない、誤解を招かない）を使用する
2. WHEN ユーザーがメッセージを読む THEN System SHALL 「AI内製化を前進させるための人材発掘と適材配置」のコンセプトを反映したトーンを使用する
3. WHEN ユーザーが任意の画面を見る THEN System SHALL 既存スペック文書の用語マッピングに準拠した用語を表示する

### 要件 7: 技術制約遵守

**ユーザーストーリー:** AI CoE運営／管理者として、既存機能を維持しながら文言更新を行いたい。

#### 受入基準

1. WHEN 文言更新が適用される THEN System SHALL 既存のAPI構造を変更しない
2. WHEN 文言更新が適用される THEN System SHALL 既存のデータベーススキーマを変更しない
3. WHEN 文言更新が適用される THEN System SHALL すべての機能的動作を維持する
4. WHEN 文言更新が適用される THEN System SHALL 既存のテストが動作することを保証する

### 要件 8: 品質保証

**ユーザーストーリー:** すべてのユーザーとして、高品質で一貫したユーザー体験を得たい。

#### 受入基準

1. WHEN ユーザーが任意の画面を見る THEN System SHALL 全画面で用語が統一されていることを保証する
2. WHEN ユーザーが日本語コンテンツを読む THEN System SHALL 自然で読みやすい日本語表現を提供する
3. WHEN ユーザーがアプリケーションを使用する THEN System SHALL 既存のユーザビリティレベルを維持する
4. WHEN ユーザーが様々なデバイスでアクセスする THEN System SHALL レスポンシブデザインを維持する
