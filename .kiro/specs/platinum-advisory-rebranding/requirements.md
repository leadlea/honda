# 要件定義書

## はじめに

製造業プラチナアドバイザリー・プラットフォームの文言・ブランディング更新により、既存の「Honda Veteran Talent Bank」から「製造業プラチナアドバイザリー」への統一されたブランド体験を提供します。

## 用語集

- **System**: 製造業プラチナアドバイザリー・プラットフォーム
- **Frontend**: React TypeScriptで構築されたユーザーインターフェース
- **Backend**: AWS Lambda上のPython APIサービス
- **User**: プラットフォームを利用する登録人材および企業ユーザー
- **Branding_Element**: 文言、色彩、メッセージトーンなどのブランド構成要素
- **Legacy_Term**: 旧「Honda Veteran Talent Bank」時代の用語
- **New_Term**: 新「製造業プラチナアドバイザリー」の用語

## 要件

### 要件 1: フロントエンド文言更新

**ユーザーストーリー:** 登録人材として、統一されたブランド体験を得るために、すべての画面で新しい用語を見たい。

#### 受入基準

1. WHEN ユーザーがアプリケーションにアクセスする THEN System SHALL 「製造業プラチナアドバイザリー」をアプリケーションタイトルとして表示する
2. WHEN ユーザーがナビゲーションを見る THEN System SHALL 「ベテラン」を「登録人材」に、「問診」を「スキル棚卸し」に表示する
3. WHEN ユーザーがダッシュボードを見る THEN System SHALL すべての統計表示とメッセージで新しい用語を使用する
4. WHEN ユーザーがプロフィール管理画面を見る THEN System SHALL 「ベテランプロフィール」を「スキルポートフォリオ」として表示する
5. WHEN ユーザーが推薦システムを見る THEN System SHALL 「推薦機会」を「参画機会レコメンド」として表示する

### 要件 2: 応募システム用語更新

**ユーザーストーリー:** 登録人材として、参画プロセスを理解するために、明確で統一された用語を見たい。

#### 受入基準

1. WHEN ユーザーが応募機能を使用する THEN System SHALL 「応募」を「参画申請」として表示する
2. WHEN ユーザーが興味表明機能を使用する THEN System SHALL 「興味表明」を「参画意向」として表示する
3. WHEN ユーザーが応募状況を確認する THEN System SHALL すべてのステータス表示で新しい用語を使用する

### 要件 3: 外部プラットフォーム用語更新

**ユーザーストーリー:** 企業ユーザーとして、人材検索時に統一されたブランド体験を得たい。

#### 受入基準

1. WHEN 企業ユーザーが外部プラットフォームにアクセスする THEN System SHALL 「ベテラン検索」を「登録人材検索」として表示する
2. WHEN 企業ユーザーが検索結果を見る THEN System SHALL すべての人材関連用語で新しい用語を使用する

### 要件 4: バックエンドメッセージ更新

**ユーザーストーリー:** システム管理者として、ログとAPIレスポンスで統一された用語を見たい。

#### 受入基準

1. WHEN APIがエラーレスポンスを返す THEN System SHALL 新しい用語を使用したエラーメッセージを返す
2. WHEN APIが成功レスポンスを返す THEN System SHALL 新しい用語を使用した成功メッセージを返す
3. WHEN システムがログを出力する THEN System SHALL すべてのログメッセージで新しい用語を使用する

### 要件 5: AI生成コンテンツ更新

**ユーザーストーリー:** 登録人材として、AI生成コンテンツでも統一されたブランド体験を得たい。

#### 受入基準

1. WHEN AIが問診コンテンツを生成する THEN System SHALL 新しい用語とメッセージトーンを使用する
2. WHEN AIがレコメンド理由を生成する THEN System SHALL 「人を活かす、新しい製造業の生態系」のコンセプトを反映する
3. WHEN AIがビジネスタイトルを生成する THEN System SHALL 製造業プラチナアドバイザリーの文脈で適切な用語を使用する

### 要件 6: ブランディング要素統一

**ユーザーストーリー:** すべてのユーザーとして、視覚的に統一されたブランド体験を得たい。

#### 受入基準

1. WHEN ユーザーがアプリケーションを使用する THEN System SHALL 製造業らしい信頼感のある色合いを表示する
2. WHEN ユーザーがメッセージを読む THEN System SHALL 「人を活かす、新しい製造業の生態系」のコンセプトを反映したトーンを使用する
3. WHEN ユーザーが任意の画面を見る THEN System SHALL 既存スペック文書の用語マッピングに準拠した用語を表示する

### 要件 7: 技術制約遵守

**ユーザーストーリー:** システム管理者として、既存機能を維持しながらブランディング更新を行いたい。

#### 受入基準

1. WHEN ブランディング更新が適用される THEN System SHALL 既存のAPI構造を変更しない
2. WHEN ブランディング更新が適用される THEN System SHALL 既存のデータベーススキーマを変更しない
3. WHEN ブランディング更新が適用される THEN System SHALL すべての機能的動作を維持する
4. WHEN ブランディング更新が適用される THEN System SHALL 既存のテストが動作することを保証する

### 要件 8: 品質保証

**ユーザーストーリー:** すべてのユーザーとして、高品質で一貫したユーザー体験を得たい。

#### 受入基準

1. WHEN ユーザーが任意の画面を見る THEN System SHALL 全画面で用語が統一されていることを保証する
2. WHEN ユーザーが日本語コンテンツを読む THEN System SHALL 自然で読みやすい日本語表現を提供する
3. WHEN ユーザーがアプリケーションを使用する THEN System SHALL 既存のユーザビリティレベルを維持する
4. WHEN ユーザーが様々なデバイスでアクセスする THEN System SHALL レスポンシブデザインを維持する
