# 要件定義書

## 概要

ダッシュボード統計表示機能は、ベテラン社員のダッシュボードに実際のデータに基づいた統計情報を表示するシステムです。現在、ダッシュボードには静的な「-」が表示されていますが、DynamoDBに保存されている実際のデータ（完了した問診数、推薦数、応募数など）を取得して表示する必要があります。

## 用語集

- **Dashboard**: ユーザーがログイン後に最初に表示される画面で、統計情報とクイックアクションを提供するインターフェース
- **Questionnaire**: AI生成された問診票で、ベテラン社員のスキルとキャリア希望を評価するためのもの
- **DynamoDB**: AWSのNoSQLデータベースサービスで、問診、推薦、応募データを保存
- **Statistics**: ユーザーの活動に関する集計データ（完了した問診数、推薦数、応募数など）

## 要件

### 要件1

**ユーザーストーリー:** ベテラン社員として、ダッシュボードで自分が完了した問診の数を確認したい。自分の活動状況を把握するために。

#### 受入基準

1. ベテラン社員がダッシュボードにアクセスする時、システムはDynamoDBから完了済み問診の数を取得すること
2. システムが問診データを取得する時、ステータスが「completed」の問診のみをカウントすること
3. 完了した問診が存在する時、ダッシュボードは実際の数値を表示すること
4. 完了した問診が存在しない時、ダッシュボードは「0」を表示すること

### 要件2

**ユーザーストーリー:** ベテラン社員として、ダッシュボードで受信した推薦機会の数を確認したい。自分に合った機会の数を把握するために。

#### 受入基準

1. ベテラン社員がダッシュボードにアクセスする時、システムはDynamoDBから推薦データを取得すること
2. システムが推薦データを取得する時、ユーザーIDに紐づく全ての推薦をカウントすること
3. 推薦が存在する時、ダッシュボードは実際の数値を表示すること
4. 推薦が存在しない時、ダッシュボードは「0」を表示すること

### 要件3

**ユーザーストーリー:** ベテラン社員として、ダッシュボードで応募した機会の数を確認したい。自分の応募活動を追跡するために。

#### 受入基準

1. ベテラン社員がダッシュボードにアクセスする時、システムはDynamoDBから応募データを取得すること
2. システムが応募データを取得する時、ユーザーIDに紐づく全ての応募をカウントすること
3. 応募が存在する時、ダッシュボードは実際の数値を表示すること
4. 応募が存在しない時、ダッシュボードは「0」を表示すること

### 要件4

**ユーザーストーリー:** ベテラン社員として、ダッシュボードでプロフィール閲覧数を確認したい。自分のプロフィールへの関心度を把握するために。

#### 受入基準

1. ベテラン社員がダッシュボードにアクセスする時、システムはプロフィール閲覧数を取得すること
2. プロフィール閲覧数が記録されている時、ダッシュボードは実際の数値を表示すること
3. プロフィール閲覧数が記録されていない時、ダッシュボードは「0」を表示すること
4. 外部リクルーターがプロフィールを閲覧する時、システムは閲覧数を増加させること

### 要件5

**ユーザーストーリー:** システム管理者として、ダッシュボードの統計データが正確に表示されることを確認したい。ユーザーが正しい情報を得られるように。

#### 受入基準

1. システムが統計データを取得する時、データベースクエリエラーを適切に処理すること
2. データ取得に失敗した時、システムはエラーメッセージをログに記録し、ユーザーには「-」または「0」を表示すること
3. ダッシュボードが読み込まれる時、統計データの取得は5秒以内に完了すること
4. 複数の統計データ取得が並行して実行される時、システムは効率的にデータを取得すること
