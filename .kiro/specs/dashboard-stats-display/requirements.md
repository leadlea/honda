# 要件定義書

## 概要

ダッシュボード統計表示機能は、社内AI人材候補（社員）のダッシュボードに実際のデータに基づいた統計情報を表示するシステムです。現在、ダッシュボードには静的な「-」が表示されていますが、DynamoDBに保存されている実際のデータ（完了したAIスキル棚卸し数、推薦数、自薦応募数など）を取得して表示する必要があります。

## 用語集

- **Dashboard**: ユーザーがログイン後に最初に表示される画面で、統計情報とクイックアクションを提供するインターフェース
- **Questionnaire**: AI生成されたAIスキル棚卸し（セルフ診断）で、社内AI人材候補のスキルとキャリア希望を評価するためのもの
- **DynamoDB**: AWSのNoSQLデータベースサービスで、AIスキル棚卸し、推薦、自薦応募データを保存
- **Statistics**: ユーザーの活動に関する集計データ（完了したAIスキル棚卸し数、推薦数、自薦応募数など）

## 要件

### 要件1

**ユーザーストーリー:** 社内AI人材候補（社員）として、ダッシュボードで自分が完了したAIスキル棚卸しの数を確認したい。自分の活動状況を把握するために。

#### 受入基準

1. 社内AI人材候補がダッシュボードにアクセスする時、システムはDynamoDBから完了済みAIスキル棚卸しの数を取得すること
2. システムがAIスキル棚卸しデータを取得する時、ステータスが「completed」のAIスキル棚卸しのみをカウントすること
3. 完了したAIスキル棚卸しが存在する時、ダッシュボードは実際の数値を表示すること
4. 完了したAIスキル棚卸しが存在しない時、ダッシュボードは「0」を表示すること

### 要件2

**ユーザーストーリー:** 社内AI人材候補（社員）として、ダッシュボードで受信したAIポジション／プロジェクト レコメンドの数を確認したい。自分に合った機会の数を把握するために。

#### 受入基準

1. 社内AI人材候補がダッシュボードにアクセスする時、システムはDynamoDBから推薦データを取得すること
2. システムが推薦データを取得する時、ユーザーIDに紐づく全ての推薦をカウントすること
3. 推薦が存在する時、ダッシュボードは実際の数値を表示すること
4. 推薦が存在しない時、ダッシュボードは「0」を表示すること

### 要件3

**ユーザーストーリー:** 社内AI人材候補（社員）として、ダッシュボードで自薦応募した機会の数を確認したい。自分の自薦応募活動を追跡するために。

#### 受入基準

1. 社内AI人材候補がダッシュボードにアクセスする時、システムはDynamoDBから自薦応募データを取得すること
2. システムが自薦応募データを取得する時、ユーザーIDに紐づく全ての自薦応募をカウントすること
3. 自薦応募が存在する時、ダッシュボードは実際の数値を表示すること
4. 自薦応募が存在しない時、ダッシュボードは「0」を表示すること

### 要件4

**ユーザーストーリー:** 社内AI人材候補（社員）として、ダッシュボードでプロフィール閲覧数を確認したい。自分のプロフィールへの関心度を把握するために。

#### 受入基準

1. 社内AI人材候補がダッシュボードにアクセスする時、システムはプロフィール閲覧数を取得すること
2. プロフィール閲覧数が記録されている時、ダッシュボードは実際の数値を表示すること
3. プロフィール閲覧数が記録されていない時、ダッシュボードは「0」を表示すること
4. AIポジションオーナーがプロフィールを閲覧する時、システムは閲覧数を増加させること

### 要件5

**ユーザーストーリー:** 社内AI人材候補（社員）として、ダッシュボードの上部に自分のAIスキルポートフォリオ見出しを表示したい。自分のプロフェッショナルなアイデンティティを確認するために。

#### 受入基準

1. 社内AI人材候補がダッシュボードにアクセスする時、システムはDynamoDBからAIスキルポートフォリオ見出しを取得すること
2. AIスキルポートフォリオ見出しが設定されている時、ダッシュボードは名前の下にAIスキルポートフォリオ見出しを表示すること
3. AIスキルポートフォリオ見出しが設定されていない時、ダッシュボードはAIスキルポートフォリオ見出しを表示しないこと
4. AIスキルポートフォリオ見出しの表示は、ウェルカムメッセージと統計セクションの間に配置されること

### 要件6

**ユーザーストーリー:** AI CoE運営／管理者として、ダッシュボードの統計データが正確に表示されることを確認したい。ユーザーが正しい情報を得られるように。

#### 受入基準

1. システムが統計データを取得する時、データベースクエリエラーを適切に処理すること
2. データ取得に失敗した時、システムはエラーメッセージをログに記録し、ユーザーには「-」または「0」を表示すること
3. ダッシュボードが読み込まれる時、統計データの取得は5秒以内に完了すること
4. 複数の統計データ取得が並行して実行される時、システムは効率的にデータを取得すること
